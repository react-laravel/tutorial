# 8.1 EEVEE Next 与 Cycles 对比

> Blender 内置两大渲染引擎：EEVEE Next（实时）和 Cycles（路径追踪）。选错引擎会浪费大量时间。本节帮你做出正确选择。

---

## 一、两个引擎简介

| 引擎 | 类型 | 原理 |
|---|---|---|
| **EEVEE Next** | 实时光栅化 | 类似游戏引擎，用近似算法 |
| **Cycles** | 路径追踪 | 模拟光线物理，逐像素计算 |

Blender 5.x 还有一个 **Workbench**，那是视口预览用的，不是出图引擎。

---

## 二、速度对比

### EEVEE Next

- 单帧渲染通常 **几百毫秒到几秒**
- 动画一分钟（1500 帧）也许 30 分钟
- 可以做实时预览

### Cycles

- 单帧渲染 **几十秒到几十分钟**（视场景复杂度）
- 动画一分钟可能要几个小时甚至一晚
- GPU 加速后 2–5 倍速

**速度差**：EEVEE 通常比 Cycles 快 **10–100 倍**。

---

## 三、画质对比

### EEVEE Next

- 接近 Cycles（Blender 5.x 有巨大提升）
- 反射、折射、全局光有近似方案
- 复杂反射、焦散、体积光在某些场合不够准

### Cycles

- 物理精准
- 全局光完全正确
- 反射、折射、焦散都是真实的
- 噪点随采样数减少

**画质差**：在简单场景中 EEVEE 几乎无差别，在复杂反射/折射时 Cycles 更真实。

---

## 四、功能差异

| 功能 | EEVEE Next | Cycles |
|---|---|---|
| 直接光 | ✅ | ✅ |
| 环境光（HDRI） | ✅ | ✅ |
| 阴影 | ✅ | ✅ |
| 反射 | ⚠️（屏幕空间 + 探针） | ✅（真实） |
| 折射 | ⚠️ | ✅ |
| 焦散 | ❌ | ✅ |
| 次表面散射（SSS） | ✅ | ✅ |
| 体积（烟雾/雾） | ✅ | ✅ |
| 全局光 | ⚠️（光照探针） | ✅ |
| 位移（真实） | ❌ | ✅ |
| 运动模糊 | ✅ | ✅ |
| 景深 | ✅ | ✅ |

---

## 五、什么时候用 EEVEE Next

- **静物、产品展示**（不需要复杂折射）
- **动画**（速度优先）
- **风格化渲染**（卡通、NPR）
- **学习/预览**
- **实时反馈**（调材质、布光时）

---

## 六、什么时候用 Cycles

- **追求真实感**（照片级）
- **复杂玻璃/焦散**
- **全局光占主导的室内**
- **商业广告级产品图**
- **有时间等待**

---

## 七、切换引擎

属性编辑器 → 渲染属性（相机图标）→ **渲染引擎** 下拉：

- Workbench
- EEVEE Next
- Cycles

**切换后**：
- 有些材质节点在不同引擎表现不同
- 光照单位保持一致（W / W/m²）
- 需要重新调整采样数

---

## 八、EEVEE Next 的关键设置

### 采样

- **视口采样**：预览的采样数（默认 16）
- **渲染采样**：最终出图的采样数（默认 64）
- 数值越高越平滑

### 环境光遮蔽（Ambient Occlusion）

- 弱化不了直接光的场景
- 默认关闭，可以开启增强接触阴影

### 屏幕空间反射

- 开启让材质有反射
- 屏幕外物体反射不准

### 辐照度探针和反射探针

- **辐照度探针**：存储间接光
- **反射探针**：存储反射信息
- 烘焙后全局光才准

这些是 EEVEE Next 的"近似方案"，后面小节简单介绍。

---

## 九、Cycles 的关键设置

### 设备

- **CPU**：慢但稳
- **GPU Compute**：快（要先在偏好里配置）
- **混合**：同时用 CPU 和 GPU

### 采样

- **视口**：10–50
- **渲染**：64–1024 甚至更多
- 越高噪点越少但越慢

### 降噪

- **视口降噪**：预览降噪，推荐开
- **渲染降噪**：输出时降噪，推荐开
- 降噪器：**OpenImageDenoise**（CPU）或 **OptiX**（NVIDIA GPU）

### 光线反弹次数

- **总最大**：反弹次数上限
- **漫射 / 光泽 / 透射** 分别控制
- 反弹越多越真越慢

---

## 十、GPU 加速配置（Cycles）

1. 编辑 → 偏好设置 → 系统
2. 找到 "CUDA / OptiX / HIP / Metal"（根据你的显卡）
3. 勾选你的显卡
4. 关闭偏好
5. 渲染属性 → 设备 → 选 "GPU 计算"

**显卡类型**：
- NVIDIA：CUDA 或 OptiX（推荐 OptiX）
- AMD：HIP
- Apple Silicon：Metal
- Intel：oneAPI

---

## 十一、降噪器说明

**降噪**能让低采样的结果看起来像高采样：

- 32 采样 + 降噪 ≈ 256 采样不降噪

### OpenImageDenoise

- Intel 开发
- 跑在 CPU 上
- 质量最好
- 推荐默认用

### OptiX Denoiser

- NVIDIA 开发
- 跑在 RTX 显卡上
- 速度极快，适合视口
- 渲染结果略逊于 OpenImageDenoise

---

## 十二、视口着色模式 ≠ 渲染引擎

很容易混淆：

| 视口模式 | 用的引擎 |
|---|---|
| 实体 | Workbench |
| 线框 | Workbench |
| 材质预览 | EEVEE Next（内置配置） |
| 渲染预览 | 当前选择的渲染引擎 |

**"渲染预览"用的才是你在渲染属性里选的引擎**。

---

## 十三、一张表：怎么选

| 你的场景 | 选 |
|---|---|
| 简单物体 + 面光 | EEVEE Next |
| 汽车漆面 + HDRI | Cycles |
| 角色展示 | 看需求，静帧 Cycles 动画 EEVEE |
| 建筑外观 | EEVEE Next |
| 建筑内部（透窗） | Cycles（间接光重要） |
| 玻璃杯里的水 | Cycles |
| 卡通/风格化 | EEVEE Next |
| 游戏资产预览 | EEVEE Next |

---

## 动手练习 8.1

### 练习 A：同场景两引擎对比
1. 场景里放一个金属球 + 一个玻璃球 + HDRI
2. 渲染属性 → 引擎 = EEVEE Next
3. `F12` 渲染，记录时间和效果
4. 引擎 = Cycles，采样 128
5. 再渲染，对比

### 练习 B：Cycles GPU 配置
1. 偏好 → 系统 → 启用你的 GPU
2. 渲染属性 → 设备 → GPU 计算
3. 渲染一次看速度提升

### 练习 C：降噪开关
1. Cycles，采样 16
2. 关降噪渲染 → 噪点严重
3. 开降噪（OpenImageDenoise）渲染 → 干净
